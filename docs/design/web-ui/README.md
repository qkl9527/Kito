# Kito Web UI 交互设计稿

本轮交付是一份独立、无需构建（buildless）的 HTML / CSS / JavaScript 设计稿，用于讨论布局、品牌表达和操作流程。它可以直接丢弃或迭代，**不是正式 Web 产品实现**：当前未实现 `kito web`，未连接后台，不调用 CLI、不上传文件，也不生成处理结果。

## 打开设计稿

在仓库根目录运行：

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory docs/design/web-ui
```

浏览器打开 [本地设计预览](http://127.0.0.1:4173)。在终端按 `Ctrl+C` 可停止预览服务。入口为 [index.html](index.html)，样式与交互分别位于 [styles.css](styles.css) 和 [app.js](app.js)，插画位于 `assets/`。

## 视觉与体验方向

设计依据 [品牌约定](../../brand.md) 中的「各有所长，一起把事情做好」，让用户先按功能找到工具，再通过伙伴形象建立熟悉感。

- **浅灰底色**：保持主要内容清楚，白色操作区域区分输入、选项与结果。
- **暖黄色动作**：突出开始、选择文件等主要操作；淡紫色首页介绍区承载小队形象。
- **独立几何伙伴**：七位伙伴分别拥有轮廓、颜色和领域符号，避免要求用户记忆角色设定。
- **明确的操作顺序**：图片流程采用「选好图片 → 选择处理方式 → 核对结果」，额外说明逐步展开。

品牌文档没有规定具体色值、字体或角色造型；本稿中的配色和几何形象是本次设计提案，并非已有品牌规范。

## 本轮范围

首页包含图片、时间、编解码、标识、密钥、视频与音频、声音创作、文本共八个工具领域，支持导航与工具搜索。前七个领域对应品牌已有的七位伙伴；文本工具已存在于 CLI，但尚无伙伴设定，因此只保留功能入口。

图片页提供本轮完整交互示例：选择或拖入单张 PNG、浏览器本地预览、使用示例素材、选择充分或快速优化，以及查看成功、没有变小、验证失败三种结果状态。真实选图只用于预览；结果固定使用「山间来信.png」的示例数据，压缩率和验证结论均不是实际运行结果，也不会生成下载文件。本稿的 20 MB 本地预览限制不代表 CLI 的处理限制。

「格式转换」与「调整尺寸」展示参数布局；其余工具页展示现有 CLI 能力与边界，尚未提供完整操作表单。未来产品的格式可用性、保存位置、后端状态和验证结论，需要由实际运行结果提供。

## 本机验证记录

2026-10-29，在当前 macOS 环境完成：

- JavaScript 语法检查与 9 个 SVG 的 XML 解析通过。
- 首页在 375、390、768、1024、1440 px 宽度下未出现横向溢出；图片页在 390 px 下按输入、选项、结果顺序排列。
- 浏览器验证示例选图、真实 PNG 本地预览、非 PNG 错误提示、伙伴搜索、Esc 关闭搜索，以及成功／无收益／失败状态切换。
- 验证窄屏导航的焦点约束、关闭后的焦点恢复，以及结果更新后聚焦结果区域。
- `scripts/cargo-local.sh fmt --check`、`scripts/cargo-local.sh clippy --all-targets -- -D warnings`、`scripts/cargo-local.sh test` 均通过。

以上为本机检查，不代表 Windows、Linux、实际手机或其他浏览器均已验证。原型没有改动 Rust CLI 源码。

## 后续产品落地建议

1. 设计 `kito web` 的本机启动、端口与退出流程，明确浏览器和 Rust 服务之间的职责及访问边界。
2. 将现有领域能力接入统一任务协议，提供真实进度、失败原因和验证报告，避免界面重复实现编解码逻辑。
3. 确定本机选文件、输出目录和冲突处理体验，延续默认不覆盖、候选验证成功后再发布的文件保护规则。
4. 根据本机后端与编解码器能力提供可用操作；为缺少 ImageMagick、OpenSSL、FFmpeg 等情况设计具体引导。
5. 在非开发者试用后完善字段文案、键盘操作与窄屏布局，再扩展其他领域表单；密钥输入和敏感信息生命周期需单独设计。
