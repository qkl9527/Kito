# Kito 奇托：伙伴约定

**各有所长，一起把事情做好。**

Kito 是一支不断加入新伙伴的工具小队。每位伙伴专注一个领域，接手一类繁琐工作，把结果处理得清楚、可靠。我们希望它轻快、亲切，也足够稳妥，能成为日常命令行工作中的长期伙伴。

Kito「奇托」是项目品牌名，CLI 入口为 `kito`。

## 一个领域，一位伙伴

伙伴对应工具领域，子命令代表这位伙伴的能力。同一领域增加能力时，优先扩展现有伙伴；出现职责独立的新领域时，再引入新伙伴。每位伙伴需要有明确的服务对象、能力范围和边界。

命令按功能命名，便于第一次使用的人理解，也便于脚本维护。角色名用于介绍、帮助信息和视觉表达，不要求用户先记住角色设定。本次不增加角色名别名。

```text
kito                         奇托工具小队
├── image                    Lumi 露米负责的图片领域
│   ├── compress             压缩图片
│   ├── convert              转换图片格式
│   └── resize               调整图片尺寸
├── time                     Tiko 提可负责的时间领域
│   ├── now                  当前时间
│   ├── from-timestamp       时间戳转日期时间
│   ├── to-timestamp         日期时间转时间戳
│   ├── convert              跨时区转换
│   ├── zones                全球时区查询
│   └── timezone             保存、查看和清除默认时区
├── codec                    Codi 可迪负责的编解码领域
│   ├── base64               Base64 编码与解码
│   ├── url                  URL 参数解析
│   └── html                 HTML/XML 实体编码与解码
├── id                       Sumi 苏米负责的指纹与标识领域
│   ├── hash                 内容摘要
│   └── uuid                 UUID 生成
├── key                      Kavi 卡维负责的密钥领域
│   ├── generate             生成 RSA / Ed25519 密钥对
│   ├── public               从私钥导出公钥
│   ├── check                检查私钥与公钥匹配
│   └── doctor               检查 OpenSSL 后端
├── video                    Vido 维多负责的视频领域
│   ├── convert / compress   转换格式与压缩视频
│   ├── trim / resize / crop 裁剪片段、缩放与裁切画面
│   ├── rotate / speed       旋转画面与调整播放速度
│   ├── concat / mute        拼接视频与去除音轨
│   ├── audio                音轨处理、音乐转换、混音与响度调整
│   └── snapshot / gif       截取 PNG 与生成 GIF
└── sound                    Echo 艾可负责的声音创作领域
    ├── presets / sfx        查看预设、一键生成音效
    ├── tone                生成音名或 Hz 对应的单音
    ├── melody              用音符与和弦生成 WAV / MIDI
    └── beat                预设与自定义鼓点
```

上图展示主要处理能力；`image` 同时提供 `info`、`formats`、`doctor`、`benchmark` 等检查与验证命令，`video` 提供 `info` 与 `doctor`。所有能力以实际 CLI 帮助和实现为准。

## 第一位伙伴：Lumi 露米

**Lumi 露米 · 图片伙伴，角色称号「光影师」。**

露米负责图片压缩、格式转换和尺寸调整，也提供图片信息、后端诊断和压缩基准。它的特点是细致：说明做了什么、验证了什么，以及还有哪些限制。

例如，未缩放的 PNG 无损优化必须守住原始像素、精度、显示相关元数据，以及完全透明像素中隐藏的 RGB。缩放会重采样像素，只能对缩放后的参考图验证编码无损；角色介绍不能淡化这些区别。默认保留输入文件，候选验证成功后才原子发布。

```sh
kito image compress icon.png
kito image convert input.png --to webp --lossless -o output.webp
kito image resize input.png --resize 1280x720
```

完整用法、依赖和质量边界见[图片工具说明](tools/image.md)。

## 第二位伙伴：Tiko 提可

**Tiko 提可 · 时间伙伴，角色称号「时刻向导」。**

提可负责 Unix 时间戳与日期时间互转、跨时区转换和全球 IANA 时区查询，支持秒、毫秒、微秒和纳秒。它让不同地区与不同精度的时间对应到明确时刻：默认输出标明时区，夏令时歧义明确报错，降低时间戳精度时说明取整；JSON 用字符串保留高精度时间戳。也可用 `--format` 自定义日期展示，完整 UTC 时刻、时间戳与时区信息仍保留在结构化报告中。

时区列表可以按名称、偏移或缩写查找，列出数据库版本及偏移参考时刻。用 `time timezone set` 保存默认时区，后续省略时区参数时自动使用；`KITO_TIMEZONE` 和单次参数可覆盖保存值。命令入口为 `time`，不增加角色名别名。当前能力不包含日程管理、提醒、计时器或自然语言日期解析。

```sh
kito time zones Shanghai
kito time from-timestamp 1704067200123 --unit ms --timezone Asia/Shanghai
kito time convert '2024-01-01 08:00:00' --from-timezone Asia/Shanghai --to-timezone America/New_York --value-only
```

完整用法、默认时区配置和自定义输出格式见[时间工具说明](tools/time.md)。

## 第三位伙伴：Codi 可迪

**Codi 可迪 · 编解码伙伴，角色称号「译码师」。**

可迪负责 Base64 编解码、URL 参数解析，以及 HTML/XML 实体转换。它耐心处理不同的数据表示：字母表和 padding 明确选择，重复参数按次序保留，实体只解码一层。它不把编码描述成加密，也不把 HTML 实体转换当作 HTML 清洗。

入口为 `kito codec`。Base64、URL 和 HTML 是同一伙伴的不同能力，具体规范和错误策略见[编解码工具说明](tools/codec.md)。

## 第四位伙伴：Sumi 苏米

**Sumi 苏米 · 标识伙伴，角色称号「印记师」。**

苏米为内容计算 Hash，也为对象生成 UUID。它的特点是细致：文件按真实字节计算摘要，UUID 明确版本，生成失败不会发布一半结果。Hash 是内容指纹；UUID 是对象标识，不能用来证明内容没有变化，也不作为密钥或授权凭证。

入口为 `kito id`，支持六种摘要算法及 UUID v4/v7。完整用法见[标识工具说明](tools/id.md)。

## 第五位伙伴：Kavi 卡维

**Kavi 卡维 · 密钥伙伴，角色称号「钥匙匠」。**

卡维通过 OpenSSL 生成 RSA 和 Ed25519 公私钥，导出公钥，并检查密钥配对。它把保存位置、私钥保护方式和后端版本交代清楚：新密钥写入独立新目录，私钥和口令不进入终端报告。RSA 的位数由用户选择，Ed25519 作为签名算法介绍，不宣传为数据加密算法。

入口为 `kito key`。密钥对生成、文件权限和口令输入比普通文本转换有更多独立约束，因此由专门伙伴负责。当前能力是密钥生成与检查，具体格式与后端要求见[密钥工具说明](tools/key.md)。

## 第六位伙伴：Vido 维多

**Vido 维多 · 视频伙伴，角色称号「剪影师」。**

维多负责把本地视频整理成适合下一步使用的片段：转换与压缩、裁剪与变形、变速与拼接，也能截取 PNG 或生成 GIF。它还在 `video audio` 中接手视频音轨和独立音乐文件的转换、剪辑、混音、淡化与响度处理。它先看清素材的轨道与尺寸，再按明确参数处理，默认保留输入，候选验证成功后才发布结果。

入口为 `kito video`，通过 FFmpeg 与 ffprobe 工作，不增加 `vido` 别名。视频处理采用重新编码，不能称作无损剪辑，也不能承诺压缩后一定更小。只保留本次操作明确使用的音视频轨，字幕、附件与原有元数据不随结果保留；这些边界在帮助和报告中交代清楚。音乐转为 WAV/FLAC 不会恢复有损源丢失的信息，单遍响度处理也不宣传为精确的交付认证。现有音视频素材的 FFmpeg 处理属于维多，从零合成声音则由 Echo 艾可负责。

```sh
kito video doctor
kito video convert clip.mov --to mp4
kito video trim clip.mp4 --start 10 --duration 5
kito video audio extract clip.mp4 --to mp3
```

格式、依赖、每项操作与安全输出规则见[视频工具说明](tools/video.md)。

## 第七位伙伴：Echo 艾可

**Echo 艾可 · 声音伙伴，角色称号「音效师」。**

艾可让一个声音想法快速变成文件：选场景生成提示音与游戏音效，用音名、和弦和休止写短旋律，用 16 格节奏生成鼓点。内置 Rust 合成器，无需 Node.js、浏览器、声卡或 FFmpeg；默认输出单声道 PCM16 WAV，旋律也可输出 MIDI 继续编曲。

入口为 `kito sound`，不增加角色名别名。合成音色不宣称是真实乐器采样，不提供 AI 自动作曲或现有音频编辑。固定噪声种子方便重复生成；校验时长和资源预算，峰值保护避免混音削波。MIDI 保存音符与节奏，音色交给播放或编曲软件选择。所有输出默认保留已有文件。

```sh
kito sound sfx success
kito sound melody 'C4 E4 G4:2 R:1 C4+E4+G4:2' --instrument bell
kito sound beat house --bpm 120 --bars 4
```

完整教程、参数和与 FFmpeg 的分工见[声音工具说明](tools/sound.md)。

## 三条共同原则

- **专注：** 每位伙伴把一个领域做好。新增能力应服务明确任务，功能名称和参数要能说明用途。
- **可信：** 保护输入，验证结果，清楚报告限制。没有验证的事情不作保证；本机成功不等于三平台已验证，重采样不宣称为原图像素无损。
- **协作：** 伙伴共用文件安全、进程管理和一致的命令习惯。让输出、报告和退出码能够服务下一步工作，减少用户在不同领域之间切换的负担。

## 表达方式

使用清楚、温和、直接的中文，保留必要的专业术语。伙伴可以有自己的性格与视觉符号，不要求统一设计成动物或宠物，也不靠繁复世界观解释简单功能。

帮助、错误和报告先告诉用户能力、结果与下一步动作。角色称呼可以增加亲切感，但不能替代功能说明、技术边界或可核对的数据。

新增伙伴或能力时，同步维护 README 中的简短入口、CLI 帮助和 `docs/tools/` 中对应工具的详细说明；历史验证报告仍记录当时的事实，不因品牌更新而改写归档数据。
