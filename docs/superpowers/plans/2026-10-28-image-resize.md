# 图片缩放实现计划

> 命名说明：本文记录采用暂名 `ctk` 时的设计或验证。项目现名为 Kito 奇托，当前命令入口为 `kito`；最新用法见 [README](../../../README.md)。

用户要求新增 `ctk image resize`，并让 compress/convert 支持 `--resize`；用户确认允许放大。沿用 Rust 和 ImageMagick 7，不新增编解码依赖；保留所有改动未提交。

## 行为约定

- `WxH` 等比放入框内，`Wx` 指定宽，`xH` 指定高，`P%` 按比例；允许放大，不裁剪、不拉伸。尺寸舍入到最近整数，最小 1 像素。
- 独立 resize 使用 `--resize SIZE`，格式优先级为显式 `--to`、输出文件扩展名、输入实际格式；默认输出 `name.resized.ext`。编码选项和格式限制沿用 convert，包括 JPEG 的显式有损参数。
- 共用 ImageMagick Lanczos 缩放流程，先确定并检查目标尺寸/内存预算，再缩放，按原样本精度量化到中间参考图，然后编码并回读验证。透明与 16-bit 输入保留对应通道能力。
- 显式缩放只授权像素重采样；不能借此跳过色彩/profile/显示元数据检查。无法可靠映射的 PNG 扩展继续保守拒绝。
- 报告记录 resize 的输入/输出尺寸、请求值和滤镜。`verified_lossless` 针对原像素；`encoding_verified_lossless` 针对变换后的参考像素。实际尺寸改变时前者为 false，后者由编码校验决定。
- compress 仍仅处理静态 PNG，批量流程可共用 resize。先缩放，再在同尺寸候选中压缩择优；原尺寸输入不参与回退。saved_bytes 使用有符号值，放大可能使文件增大。
- 未传 resize 的行为和后端依赖不变。原图保护、原子发布、并发预算和错误处理继续复用。
