# Kito Web UI 首版实现计划

> 使用 writing-plans、subagent-driven-development 与 verification-before-completion 工作流。用户已批准设计，并授权自主决定、连续实现；不执行 commit、push 或发布。

**Goal:** `kito web` 在回环地址启动内嵌网页，为八个现有领域提供真实常用操作、任务状态与结果下载。

**Architecture:** Axum/Tokio 提供本机 HTTP 服务，静态资源编译进入二进制。服务接收浏览器选择的文件，保存到会话专属临时目录；严格白名单把结构化请求转换为当前 Kito 二进制的参数数组，复用现有 CLI 校验、原子发布和结果报告。后台任务有并发、输入、输出、时间与会话数量上限。

**Tech Stack:** Rust、Axum 0.8、Tokio 1、原生 HTML/CSS/JavaScript；不增加前端构建或运行依赖。

**Spec:** `docs/design/web-ui/README.md`、`docs/brand.md`、本轮用户指示。首页称「工具小队」，不使用「工作台」。

## 全局约束与决策

- 不修改原始输入，不允许前端指定任意服务器路径、执行程序或 argv；所有输出在任务隔离目录，浏览器下载。
- 只监听 `127.0.0.1`；默认端口 0 自动分配，`--port` 可指定；默认尝试打开浏览器，`--no-open` 关闭此行为。
- 每次启动生成系统安全随机 token；URL fragment 引导前端，API 使用 `X-Kito-Token`；校验 Host、Origin，拒绝跨站请求。
- 单文件 64 MiB、会话上传总量 256 MiB、文本参数 64 KiB、同时最多 2 个任务、最多保留 64 个任务、任务最多 180 秒；输出文件总量最多 256 MiB/任务。运行中任务拒绝清空会话；退出清理。
- 八领域首版常用能力：图片 compress/convert/resize/info/exif；时间 now/from-timestamp/to-timestamp/convert/zones；codec base64/url/html；id hash/uuid；text count/dedupe/case；key generate/public/check；video convert/compress/trim/resize/mute/snapshot/gif/audio-extract/audio-convert；sound sfx/tone/melody/beat/presets。不宣称覆盖 CLI 全部高级选项。
- 临时文件与输出可能含私钥：口令只用 stdin，私钥只允许文件下载，不进入 JSON；页面和 API no-store，不使用持久本地存储保存输入或结果。
- 当前仓库全部为未跟踪文件且没有 HEAD。常规 worktree 无基线可创建，不能为此擅自提交；在当前用户工作目录增量实现，保持设计稿归档。

## 接口约定

- `GET /api/info` → `{version, limits:{upload_bytes,...}, backends:{image:{available,message},video:{...},key:{...}}}`。
- `POST /api/uploads?name=<encoded>`：二进制原始字节 → `{id,name,size}`。
- `POST /api/jobs`：`{tool,action,params:{string:string},files:[uploadId]}` → 202 `{id,state:"running"}`。
- `GET /api/jobs/{id}` → `{id,state:"running"|"completed"|"failed",stdout,report,files:[{id,name,size,mime}],error}`。
- `GET /api/files/{id}`：鉴权后下载字节，前端 fetch 转 Blob；无 token 的链接不能读取文件。
- `DELETE /api/session`：任务空闲时清理本次上传与结果。
- API 错误统一 `{error:中文消息}`；请求不包含任意本机路径。前端所有原始结果以 textContent 展示。
- `src/web/commands.rs` 提供 `RunRequest` 与 `prepare(&RunRequest, &[PathBuf], &Path) -> anyhow::Result<PreparedCommand>`。第三个参数是已创建的任务 output 目录。`PreparedCommand {args:Vec<OsString>, stdin:Option<Vec<u8>>}`，输出命令一律在指定目录内。

## Review Focus

- 恶意 Host/Origin、缺失 token、路径穿越、用户字段被解释为 CLI 选项。
- binary stdin 与下载字节精确保留；Base64 解码不得有损转为文本。
- 并发、超时、超额输出与取消后不能留下不受控子进程或发布部分结果。
- 私钥口令不可进入 argv/报告；输出文件只来自成功任务且拒绝符号链接。
- 浏览器断连、文件错误、缺少后端时恢复操作且保留原输入。
