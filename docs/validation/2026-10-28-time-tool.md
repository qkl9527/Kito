## Review 及修复

独立只读 review 检查了整数精度、DST、配置优先级与历史 offset。发现 1 项 P2：Chrono 的宽松格式解析可能将漏写分隔符的 `2024-01-112:00:00` 解释为 2024-01-11 02:00:00。

新增 `malformed_date_boundaries_cannot_be_reinterpreted_as_another_day` 回归测试，先确认它因错误接受该输入而失败，再增加固定字段宽度和分隔符检查。修复后 15 项时间测试、81 项完整测试、fmt、Clippy 和 release 构建重新通过。没有未处理的 review 问题。

## 可复现示例

```sh
./target/release/kito time zones Shanghai
# Asia/Shanghai  +08:00  CST（同时输出数据库版本和参考时刻）

./target/release/kito time from-timestamp 1704067200123456 --timezone Asia/Shanghai --value-only
# 2024-01-01T08:00:00.123456+08:00

./target/release/kito time to-timestamp '2024-01-01 08:00:00.123456' --timezone Asia/Shanghai --unit us --value-only
# 1704067200123456

./target/release/kito time convert '2024-01-01 08:00:00' --from-timezone Asia/Shanghai --to-timezone America/New_York --value-only
# 2023-12-31T19:00:00-05:00

./target/release/kito time zones New_York --at '2024-07-01T00:00:00Z' --json
# America/New_York 对应 utc_offset=-04:00、abbreviation=EDT
```

## 使用边界

auto 的位数规则不能证明真实单位；接近 Unix 纪元、历史日期或非典型位数应显式使用 `--unit`。时区规则由构建时内置的数据库决定，并非实时更新。日期年份限定为 0000–9999；不支持闰秒或自然语言日期。单值模式刻意只输出结果，精度损失等详情应查看默认文本或 JSON。
